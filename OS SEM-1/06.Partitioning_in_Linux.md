## Source coverage and important cautions

The source PDF discusses: - What Linux disk partitioning is and why it
matters. - Common Linux partitions and their purposes. - GPT/UEFI and
MBR/legacy boot concepts. - Dual-booting Linux with Windows 11. -
Suggested home/SOHO, server, and enterprise LAMP partition layouts. -
Filesystem choices, mount options, swap, disk encryption, backups, and
LVM.

**Important:** The partition sizes in this document are examples from
the PDF, not universal rules. Actual sizes depend on disk capacity, RAM,
hibernation requirements, workload, installed software, retention of
logs, database growth, filesystem, encryption, and backup strategy.

### Accuracy clarifications

-   A partition is a logical region of a disk. It does not automatically
    have its own filesystem or mount point; those are configured
    separately. Swap partitions are used as swap rather than mounted
    like ordinary filesystems.
-   Separate partitions can reduce the chance that one area filling up
    will consume space reserved for another, but they do not guarantee
    that the operating system will remain healthy.
-   A separate `/home` partition can make reinstallations easier, but it
    is **not a backup** and does not guarantee that personal data or
    settings will survive every reinstall.
-   Swap is disk-backed memory support, not equivalent in speed to RAM.
    Swap sizing is workload-dependent; hibernation requirements depend
    on the system and configuration and are not always solved by a
    simple "swap equals RAM" rule.
-   `/boot` and `/boot/efi` are not interchangeable. `/boot` commonly
    stores kernel and initramfs files; `/boot/efi` is a common mount
    point for the EFI System Partition (ESP) on UEFI systems.
-   For Windows dual-boot, protect existing Windows and EFI partitions.
    Do not format a partition unless you have positively identified it
    and intend to erase its contents.
-   Mount options such as `noexec`, `nosuid`, and `nodev` can reduce
    certain risks, but they are not complete security boundaries and do
    not block every way malware can run.
-   LVM can make storage allocation more flexible, but resizing still
    depends on free space, filesystem capabilities, and the correct
    procedure. Shrinking filesystems can be risky.
-   The PDF's enterprise section heading says "On single disk 1 GB,"
    while the body describes a **1 TB** disk. The layout is treated here
    as a 1 TB example.
-   The PDF has 7 pages of substantive content and an additional
    effectively blank page.

## 1. What Is Disk Partitioning?

### Definition

**Disk partitioning** is the process of dividing a physical storage
device, such as an HDD or SSD, into logical regions called
**partitions**.

A partition can be formatted with a filesystem, used as swap, or used
for another storage purpose. A filesystem can then be mounted into the
Linux directory tree at a mount point such as `/`, `/home`, or `/var`.

### Basic storage structure

``` mermaid
flowchart TD
    D[Physical SSD or HDD] --> P[Partition table]
    P --> P1[Partition 1]
    P --> P2[Partition 2]
    P --> P3[Partition 3]
    P1 --> F1[Filesystem or boot data]
    P2 --> F2[Filesystem]
    P3 --> S[Swap or another purpose]
    F2 --> M[Mounted at a directory such as /home]
```

The partition table records how the disk is divided. A partition is not
the same thing as a filesystem, and a mount point is a directory where a
filesystem becomes accessible.

## 2. Why Partitioning Matters

### 2.1 System stability and space isolation

If all system files, user files, logs, and application data share one
filesystem, one runaway process can fill that filesystem and affect many
services.

Separate filesystems can reserve space for different purposes. For
example, a rapidly growing `/var/log` filesystem may fill without using
all the space allocated to `/`.

**Limitation:** A full partition can still break services that need to
write there. Partitioning reduces some forms of interference; it does
not automatically prevent failures.

### 2.2 Easier upgrades and reinstallations

A separate `/home` filesystem can keep personal files and user
configuration separate from the root filesystem. During an OS reinstall,
an installer may allow the existing `/home` filesystem to be reused
without formatting it.

**Important:** Select the correct partition and avoid formatting it if
you intend to keep its contents. Back up data first. Reusing a home
directory with a different distribution or user-ID setup can still
create configuration or permission issues.

### 2.3 Security and mount policies

Different filesystems can be mounted with different options. Examples
include: - `ro`: mount read-only. - `noexec`: prevent direct execution
of binaries from that mount in normal circumstances. - `nosuid`: ignore
set-user-ID and set-group-ID bits on that mount. - `nodev`: do not
interpret device-special files on that mount.

These options can reduce some risks when applied appropriately. They do
not replace normal file permissions, updates, least privilege,
encryption, or monitoring.

### 2.4 Storage planning and swap

Separating large or fast-growing data, such as database files and logs,
can simplify capacity management. Swap can help manage memory pressure
and may be part of a hibernation setup.

**Performance clarification:** Swap is much slower than RAM on typical
storage. It does not make disk memory equivalent to physical memory or
guarantee that the system will never freeze.

### Summary

Partitioning is useful for: - Separating operating-system files from
user and application data. - Managing storage growth. - Applying
filesystem-specific mount options. - Supporting boot requirements. -
Making some reinstallations and maintenance tasks easier.

It also adds complexity: an undersized partition can fill while another
partition still has free space.

### Understanding `/` (root)

The root filesystem is mounted at `/`. If `/home`, `/var`, and other
directories are not separate mounts, their contents reside on the root
filesystem.

### Understanding `/home`

A separate `/home` can help separate user data from the OS, but the
directory does not have to be a separate partition. It may live on the
root filesystem, an LVM logical volume, a network filesystem, or another
storage arrangement.

### Understanding `/boot` and `/boot/efi`

-   `/boot`: commonly contains Linux kernel images and initramfs/initrd
    files.
-   `/boot/efi`: a common mount point for the EFI System Partition,
    which contains UEFI bootloader files.

A UEFI system normally has an ESP. Whether a separate `/boot` is needed
depends on the distribution, bootloader, encryption, filesystem, and
system design.

### Understanding `/var`

`/var` holds data that changes during normal operation. Separating it is
especially useful when logs, caches, queues, or application data may
grow rapidly. However, the size must match expected workload and
retention policies.

### UEFI boot at a high level

``` mermaid
flowchart TD
    A[Power on] --> B[UEFI firmware]
    B --> C[EFI System Partition: FAT filesystem]
    C --> D[Bootloader file]
    D --> E[Linux kernel and initramfs]
    E --> F[Linux userspace starts]
```

UEFI firmware can load a bootloader from the EFI System Partition. The
bootloader then starts the Linux kernel.

### Exam point

**GPT is a partition-table format; UEFI is a firmware interface.** UEFI
systems commonly use GPT, but avoid defining the terms as if they were
the same thing.

## 5. Dual-Boot Linux Alongside Windows 11

Dual-booting means installing two operating systems on one computer and
choosing which one to start at boot time.

### Before you begin

1.  **Make a full backup** of important files to a separate drive or
    trusted backup destination.
2.  **Check Windows BitLocker/device encryption.** Save the recovery
    key. Ubuntu's official installation guidance explains that its
    installer may be unable to safely install alongside a
    BitLocker-encrypted Windows installation.
3.  **Check Windows Fast Startup and hibernation settings** if you plan
    to access Windows files from Linux. Avoid writing to Windows
    filesystems that may be in an unsafe or hibernated state; follow
    current guidance for your Windows and Linux versions.
4.  **Use Windows Disk Management to shrink the Windows volume** if that
    is the chosen preparation method, leaving unallocated space for
    Linux. Do not delete Windows partitions just to create space.
5.  Confirm whether the machine boots in UEFI mode and identify the
    existing EFI System Partition.
6.  Prepare the Linux installer USB and verify that the correct disk is
    selected before making changes.

### BitLocker warning

If BitLocker is enabled, do not assume the Linux installer can read or
resize the encrypted Windows installation. Check the current installer
documentation and decide on a supported approach before continuing.
Turning off encryption can have security implications; save recovery
keys and understand your organization's or device's policy before
changing it.

Reusing the existing ESP is often appropriate; follow the specific

### Installation checklist

-   Boot the USB installer in the intended firmware mode (usually UEFI
    for a modern Windows 11 setup).
-   Choose the guided "install alongside" option if it correctly detects
    the existing system and suits your needs; otherwise use manual
    partitioning only if you can identify every partition confidently.
-   Assign Linux partitions and mount points carefully.
-   Preserve the Windows partitions and existing EFI partition.
-   Verify the final summary before confirming writes to disk.
-   After installation, test that both Windows and Linux can boot.

**Destructive warning:** Formatting or deleting the wrong partition can
erase Windows, personal files, or boot files. If you are unsure which
partition is which, stop rather than guessing.

### Disk encryption and backups

-   Consider full-disk or filesystem encryption, such as a LUKS-based
    installation, particularly for portable devices and sensitive data.
-   Keep recovery information safe.
-   Maintain backups on a separate physical device or reliable remote
    destination.
-   Test that backups can actually be restored.

**Important distinction:** Encryption protects confidentiality in
specific situations; backups protect recoverability. They solve
different problems.

Servers may store logs, databases, web content, queues, and backups.
Separating high-growth areas can help prevent one workload from

The table is a planning example, not a universal server design. Some
services store their data under `/var/lib`; some administrators separate

network storage, or multiple physical devices.

### Why isolate `/var`?

If logs or package caches grow unexpectedly, a separate `/var`
filesystem may prevent those files from consuming all free space on `/`.
However, services can still fail if their own filesystem fills. Log
rotation, monitoring, alerting, and retention policies remain important.

### Why separate database storage?

Databases can grow quickly and may have specific performance, backup,
and recovery requirements. A dedicated filesystem or logical volume for
database files can make capacity management and monitoring easier.

It does **not** mean database growth can never affect the service: the
database filesystem can still fill, and the database may depend on other
filesystems for logs, temporary files, or configuration.

before adding it to a real system.

## 9. Static Partitions vs. LVM

### Traditional/static partitioning

Partitions are defined directly in the disk's partition table. A simple
system may use a few partitions for EFI, root, home, and swap.

Advantages: - Straightforward structure. - Familiar to beginners. -
Often sufficient for desktops and simple systems.

Limitations: - Reallocating space between partitions can be difficult. -
Resizing may require unmounting, special tools, or downtime. - Poor
initial sizing can leave one filesystem full while space remains
elsewhere.

### Logical Volume Manager (LVM)

LVM adds a flexible storage layer between physical storage and
filesystems.

``` mermaid
flowchart TD
    D1[Physical disk / partition A] --> PV[Physical volumes]
    D2[Physical disk / partition B] --> PV
    PV --> VG[Volume group: shared capacity pool]
    VG --> LV1[Logical volume: root]
    VG --> LV2[Logical volume: var]
    VG --> LV3[Logical volume: data]
    LV1 --> F1[Filesystem]
    LV2 --> F2[Filesystem]
    LV3 --> F3[Filesystem]
```

### LVM terminology

-   **Physical Volume (PV):** A storage device or partition initialized
    for LVM.
-   **Volume Group (VG):** A pool of capacity assembled from physical
    volumes.
-   **Logical Volume (LV):** A virtual block device allocated from a
    volume group.
-   **Filesystem:** Created on a logical volume and mounted at a
    directory, just as it can be on a traditional partition.

### Why use LVM?

-   Allocate storage from a shared pool.
-   Extend logical volumes when the volume group has free capacity.
-   Manage logical storage separately from the underlying physical
    layout.
-   In supported configurations, combine storage from more than one
    physical volume.

LVM is not magic: the volume group must have free capacity (or
additional storage must be added), and the filesystem must be resized
appropriately. Reducing volumes is particularly risky and must follow
the filesystem-specific procedure.

### Useful inspection commands

``` bash
lsblk -f
```

Lists block devices, partitions, filesystem types, labels, UUIDs, and
mount points (details vary by util-linux version).

``` bash
findmnt
```

Displays mounted filesystems and their mount points.

``` bash
df -hT
```

Shows filesystem capacity, available space, usage, and filesystem type
in a human-readable form.

``` bash
sudo pvs
sudo vgs
sudo lvs
```

On a system with LVM tools and LVM configured, these commands inspect
physical volumes, volume groups, and logical volumes.

``` bash
sudo blkid
```

Displays block-device attributes such as filesystem types and UUIDs.

These commands are for inspection. Creating, formatting, resizing, or
deleting partitions and volumes is much riskier and requires a backup
and a verified target device.

## 10. Practical Workflow for Planning Partitions

Use this planning sequence before installing Linux or redesigning a
server's storage.

``` mermaid
flowchart TD
    A[Identify device, capacity and boot mode] --> B[Back up important data]
    B --> C[Determine workload and growth needs]
    C --> D[Choose filesystems and mount points]
    D --> E{Need flexible allocation?}
    E -->|Yes| F[Consider LVM]
    E -->|No| G[Plan traditional partitions]
    F --> H[Review sizes, encryption and mount options]
    G --> H
    H --> I[Verify every target partition]
    I --> J[Review installer summary before writing changes]
    J --> K[Install and test boot, mounts and available space]
    K --> L[Monitor usage and test backups]
```

### Questions to answer first

1.  How large is the disk, and is it an HDD, SATA SSD, or NVMe SSD?
2.  Is the machine UEFI/GPT or legacy BIOS/MBR?
3.  Will Windows remain installed?
4.  How much space will the OS and applications need?
5.  How much user, database, web, or log data is expected?
6.  Is hibernation required, and what swap arrangement does the
    distribution recommend?
7.  Is encryption required?
8.  Will storage need to grow over time?
9.  Are backups available and tested?
10. Which directories need separate filesystems for operational reasons?

## 11. Common Mistakes and Safety Warnings

-   **Formatting the wrong partition:** Can permanently destroy data.
    Confirm device names, sizes, filesystem types, and partition roles.
-   **Assuming `/home` is a backup:** A separate partition is still on
    the same physical device and can be lost through device failure,
    mistakes, or damage.
-   **Using one-size-fits-all partition sizes:** Server workloads differ
    greatly; size based on actual capacity and growth expectations.
-   **Confusing `/boot` and `/boot/efi`:** They have different purposes.
-   **Treating swap as fast RAM:** Swap is slower and cannot guarantee
    that memory pressure will never cause trouble.
-   **Assuming `noexec` makes a partition malware-proof:** It is only
    one layer of defence.
-   **Leaving logs unmanaged:** Separate `/var/log` can help isolate
    capacity but still needs monitoring and log rotation.
-   **Resizing a filesystem without a backup:** A wrong sequence or
    unexpected failure can cause data loss.
-   **Shrinking an LVM volume before shrinking its filesystem:** The
    order and commands depend on filesystem type; doing this incorrectly
    can destroy data.
-   **Changing BitLocker settings without recovery information:**
    Firmware or boot changes can trigger recovery prompts. Keep the key
    safely available.
-   **Blindly creating another EFI partition:** Identify and follow the
    installation guide for the existing ESP and firmware mode.

## 12. Exam Preparation

### Important definitions

-   **Partitioning:** Dividing a storage device into logical regions.
-   **Partition table:** Metadata that describes the partitions on a
    disk.
-   **Filesystem:** A method of organizing files and directories on a
    storage volume.
-   **Mount point:** A directory where a filesystem is attached to the
    Linux directory tree.
-   **Root filesystem (`/`):** The filesystem mounted at the root of the
    directory tree.
-   **`/home`:** Common location for regular users' personal
    directories.
-   **Swap:** Disk-backed storage used by the virtual-memory system.
-   **EFI System Partition (ESP):** A FAT-formatted partition used by
    UEFI firmware to access bootloader files.
-   **GPT:** GUID Partition Table, a modern partition-table format.
-   **MBR:** Master Boot Record partitioning scheme, associated with
    older partitioning layouts.
-   **LVM:** Logical Volume Manager, a flexible storage-allocation
    layer.
-   **Mount option:** A setting that controls aspects of how a

### Quick revision sheet

-   Partitioning divides a disk into logical regions.
-   Partition, filesystem, and mount point are different concepts.
-   `/` contains the root filesystem; `/home` commonly stores user
    files.
-   `/boot` commonly stores kernel/initramfs files; `/boot/efi` is a
    common ESP mount point on UEFI systems.
-   `/var` contains changing data such as logs, caches, and application
    state.
-   Swap supports virtual memory and may support hibernation when
    configured appropriately.
-   GPT is a partition-table format; UEFI is a firmware interface.
-   Separate partitions can isolate capacity and allow different mount
    options, but add sizing and maintenance complexity.
-   LVM pools storage and provides flexible logical volumes, but free
    capacity and filesystem-specific procedures still matter.
-   A separate `/home`, snapshots, and encryption do not replace
    independent backups.
-   Always verify the target device and review the final installer
    summary before committing partition changes.
