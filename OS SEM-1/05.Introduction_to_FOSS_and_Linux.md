## 1. FOSS: Free and Open Source Software

### Definition

**FOSS** stands for **Free and Open Source Software**. It describes
software that gives users meaningful rights to use, study, modify, and
share the software under its license.

Here, *free* mainly means **freedom**, not necessarily zero price. FOSS
may be distributed for free or sold commercially. What matters is the
license and the freedoms it grants.

### Why FOSS matters

With proprietary software, users may be unable to inspect or change the
source code. If the program has a bug or no longer meets a user's needs,
the user may depend entirely on the vendor.

FOSS can allow users and communities to: - Inspect how software works. -
Fix bugs or adapt software. - Share copies with others. - Share modified
versions, subject to the license terms. - Learn from real-world source
code and collaborate on improvements.

### Source code and executable code

-   **Source code:** Human-readable instructions written by developers.
-   **Executable/binary:** A form prepared for a computer to run.
-   **License:** The legal terms defining how software can be used,
    modified, and redistributed.

``` text
Source code
    |
    | compiler / interpreter / build tools
    v
Runnable program
```

Access to source code is essential for the freedom to study and modify a
program.

### FOSS does not necessarily mean

-   The software costs nothing.
-   The software has no bugs.
-   Anyone may ignore its license.
-   Every FOSS license has identical conditions.
-   The software is automatically secure.

**Exam point:** Free software is about users' freedoms, not simply the
price.

### What is the GNU GPL?

The **GNU General Public License (GPL)** is a free-software license. It
grants rights to use, study, modify, and redistribute covered software
while imposing conditions on redistribution. GPL versions differ, so the
actual license version and its terms matter.

The GPL is commonly described as a **copyleft** license: when covered
modified versions are distributed, specified licensing and source-code
obligations apply. Do not assume every open-source license is copyleft;
some use permissive terms.

## 3. Linux Kernel, GNU/Linux, and Distributions

### What is Linux?

Strictly speaking, **Linux is the kernel**: the central component that
manages hardware resources and provides core services to programs.

The kernel helps manage: - CPU time and processes. - Memory and virtual
address spaces. - Devices and device drivers. - Filesystems and storage
access. - Networking. - Security and access controls. - Communication
between processes.

Android uses the **Linux kernel**, but it is not simply a standard

## 4. Major Linux Features and System Access Modes

### Features discussed in the PDF

-   **Multi-user:** Multiple user accounts can use the system with
    separate identities and permissions.
-   **Multitasking:** The OS manages multiple executing tasks, sharing
    CPU time where appropriate.
-   **Multithreading:** A process can contain multiple threads of
    execution.
-   **Multiprocessing:** The system can use multiple CPUs or CPU cores.
-   **Networking and clustering:** Linux supports networking and can be
    used in clustered systems.
-   **Hardware range:** Linux runs on many architectures, from small
    embedded systems to servers and supercomputers.
-   **Filesystem support:** Linux supports several filesystem formats,
    including ext4, XFS, Btrfs, and others, depending on kernel
    configuration and installed tools.
-   **Privilege separation:** Ordinary users normally have fewer
    privileges than the root administrator, helping limit accidental or
    unauthorized changes.

### Security qualification

The PDF suggests Linux has "native immunity" to traditional virus
vulnerabilities. That wording is too strong. Linux has useful security
mechanisms, but it is **not immune to malware**. Safe administration
still requires updates, least-privilege access, secure configuration,
backups, and care with downloaded software and commands.

### Three system access scenarios

1.  **Command-line-only system:** The system starts in a text-based
    environment; users work through a shell and CLI tools.
2.  **Manual/hybrid graphical environment:** The system may start in a
    text target and the graphical layer is started when needed.
3.  **Graphical desktop by default:** The system starts a desktop
    environment, and a terminal emulator provides access to a shell.

A graphical interface is optional on many Linux installations,
especially servers. A terminal emulator is a graphical application that
displays a shell session; the terminal emulator and shell are different
things.

## 5. Linux Boot Process

### Overview

Booting is the process of moving a computer from powered-off/reset state
to a usable operating system.

### Simplified boot sequence

``` mermaid
flowchart TD
    A[Power on / reset] --> B[BIOS or UEFI initializes hardware]
    B --> C[Bootloader is selected]
    C --> D[Bootloader loads Linux kernel and often initramfs]
    D --> E[Kernel initializes memory and devices]
    E --> F[Temporary or initial root filesystem is prepared]
    F --> G[Real root filesystem is mounted]
    G --> H[Kernel starts PID 1: init system]
    H --> I[Services and system targets start]
    I --> J[Login prompt or graphical login]
    J --> K[User session]
```

### Step-by-step explanation

1.  **Power on and firmware:** BIOS or UEFI initializes essential
    hardware and chooses a boot device.
2.  **Bootloader:** A bootloader such as GRUB loads the selected kernel
    and may load an initramfs image.
3.  **Kernel startup:** The kernel initializes core subsystems, memory
    management, and available devices/drivers.
4.  **Initial root environment:** An initramfs may provide tools needed
    to locate and mount the real root filesystem, for example when
    storage drivers or encryption are required.
5.  **Root filesystem:** The system mounts the real root filesystem and
    transitions into the normal operating environment.
6.  **PID 1:** The kernel starts the initial userspace process,
    conventionally process ID 1. On many modern distributions this is
    `systemd`; other init systems exist.
7.  **Services:** The init system starts configured services and reaches
    the appropriate target/runlevel.
8.  **Login:** The system presents a text login prompt or graphical
    login manager.

### Important clarification

The PDF's simplified sequence says `init` starts with "method ID zero."
The standard term is **process ID (PID) 1**, not method ID zero. Also,
initramfs and UEFI details are omitted from many introductory diagrams;
the exact path varies by machine and distribution.

### Useful commands after boot

``` bash
uname -r
```

Displays the running kernel release.

``` bash
ps -p 1 -o pid,comm,args
```

Shows the command associated with process ID 1.

``` bash
systemctl get-default
```

On systemd-based systems, displays the default system target.

``` bash
journalctl -b
```

On systems using systemd's journal, shows logs from the current boot.
Permissions and available logs may vary.

## 6. Linux Kernel Architecture and User/Kernel Space

### Monolithic but modular design

The PDF describes Linux as a **monolithic kernel with modular
capabilities**.

-   **Monolithic:** Core services such as process management, memory
    management, networking, and filesystem support operate in kernel
    space.
-   **Modular:** Supported kernel modules can add functionality, such as
    certain device drivers or filesystem components, without rebuilding
    the entire kernel.
-   **Loadable kernel modules (LKMs):** Modules may be loaded or
    unloaded at runtime when supported and when dependencies and
    security policy allow it.

"Monolithic" does not mean the kernel has no internal structure. Linux
has distinct subsystems and interfaces, but many core services share
kernel privilege and address space.

## 7. Linux Filesystem Hierarchy Standard (FHS)

### What is the filesystem hierarchy?

Linux organizes files in a single directory tree rooted at `/` (the
**root directory**). Other filesystems can be attached to directories
called **mount points**.

The Filesystem Hierarchy Standard (FHS) provides conventions for where
many types of files should be placed. It is a standard and guideline,
not a guarantee that every distribution has exactly the same layout.

### Directory tree

``` text
/
├── bin       Essential user commands (may link to /usr/bin)
├── boot      Bootloader files, kernel images, initramfs
├── dev       Device files and device interfaces
├── etc       System-wide configuration
├── home      Regular users' home directories
├── lib       Essential libraries (may link to /usr/lib)
├── media     Mount points for removable media
├── mnt       Temporary/manual mount points
├── opt       Optional/add-on application packages
├── proc      Virtual view of process and kernel information
├── root      Home directory of the root administrator
├── run       Volatile runtime data
├── sbin      Essential system commands (may link to /usr/sbin)
├── srv       Data served by services
├── sys       Kernel/device information through sysfs
├── tmp       Temporary files
├── usr       Most user-space applications, libraries and shared data
└── var       Variable data, such as logs, caches and spools
```

### Important distinctions

-   `/` is the **root directory**; `/root` is the root user's **home
    directory**.
-   `/home/student` is an example of a regular user's home directory.
-   `/etc` usually stores configuration, not ordinary personal
    documents.
-   `/proc` and `/sys` are virtual interfaces, not ordinary collections
    of files stored on disk in the usual way.
-   `/tmp` and `/var/tmp` may have different cleanup expectations; do
    not assume temporary data is permanent.
-   `/dev` entries represent device interfaces; they are not necessarily
    regular files containing device data.
-   On merged-`/usr` systems, `/bin`, `/sbin`, and `/lib` may be
    symbolic links into `/usr`. Check the actual machine rather than
    assuming one layout.

### Inspect the hierarchy

``` bash
pwd
```

Prints the current working directory.

``` bash
ls /
```

Lists entries in the root directory.

``` bash
ls -ld /bin /sbin /lib /usr/bin
```

Shows directory metadata and can help identify whether traditional paths
are symbolic links.

``` bash
ls /proc
cat /proc/meminfo
```

Shows some entries in `/proc` and reads memory information exposed by
the running kernel.

``` bash
find /etc -maxdepth 1 -type f
```

Lists regular files directly under `/etc` (not all files recursively).
Access permissions and distribution layout affect results.

**Safety tip:** Commands that only list or inspect files are generally
safer than commands that modify or delete them. Be especially careful
with recursive deletion, ownership changes, and permission changes.

## 9. Exam Preparation

### Essential definitions

-   **FOSS:** Software distributed under terms that allow users to use,
    study, modify, and share it.
-   **Kernel:** The core of an operating system that manages resources
    and provides essential services.
-   **Linux distribution:** An installable operating system built around
    the Linux kernel and a selected collection of system software.
-   **Shell:** A program that interprets commands and allows users to
    interact with the operating system.
-   **System call:** A controlled interface through which a user-space
    program requests a service from the kernel.
-   **User space:** The execution environment in which ordinary
    applications generally run with restricted privileges.
-   **Kernel space:** The privileged environment in which the kernel
    executes.
-   **Bootloader:** Software that loads or starts the operating-system
    kernel.
-   **Init system:** The first userspace process, normally PID 1,
    responsible for starting and managing system services.
-   **FHS:** A standard defining conventions for directory and file
    placement in Unix-like systems.
-   **VFS:** The kernel layer that offers a common interface to
    different filesystem implementations.
-   **Kernel module:** Code that can add supported functionality to a
    running kernel without necessarily rebuilding the whole kernel.

### Questions to practise

**Short-answer questions** 1. What does FOSS stand for? 2. Why does
"free software" not necessarily mean software that costs nothing? 3.
State the four freedoms. 4. Differentiate the Linux kernel and a Linux
distribution. 5. What is the purpose of a shell? 6. What is the role of
a bootloader? 7. What is PID 1? 8. What is the purpose of `/etc`,
`/home`, `/proc`, and `/var`?

**Long-answer questions** 1. Explain the history and significance of
FOSS and the four freedoms. 2. Draw and explain the major stages of the
Linux boot process. 3. Explain Linux kernel architecture, including user
space, kernel space, and major subsystems. 4. Explain the Linux
filesystem hierarchy with a labelled directory tree. 5. Describe the
major components included in a Linux distribution.

**Diagram practice** - User → applications → system calls → kernel →
hardware. - Linux boot process. - User space vs. kernel space. - Root
filesystem directory tree.

**Practical command practice** 1. Display your current directory. 2.
List entries in `/`. 3. Display the running kernel release. 4. Identify
the process running as PID 1. 5. Display memory information from
`/proc/meminfo`. 6. Check whether `/bin` is a directory or a symbolic
link.

### Quick revision sheet

-   **FOSS = freedom, not price.**
-   **Four freedoms:** run, study/change, redistribute, distribute
    modified versions.
-   **Linux = kernel; distribution = kernel + selected system
    software.**
-   **Kernel jobs:** process scheduling, memory management, devices,
    filesystems, networking, IPC, security.
-   **User space:** restricted application environment. **Kernel
    space:** privileged core.
-   **Boot flow:** firmware → bootloader → kernel/initramfs → root
    filesystem → PID 1 → services → login.
-   **FHS:** `/etc` configuration, `/home` user files, `/root`
    administrator home, `/boot` boot files, `/dev` devices, `/proc`
    process/kernel information, `/sys` device/kernel information, `/usr`
    applications and shared data, `/var` changing data, `/tmp` temporary
    files.
-   **Security:** Linux has security mechanisms but is not
    malware-proof.
-   **Remember:** directory layouts, boot details, and init systems vary
    by distribution.

### Practice exercises with answers

1.  **Question:** Is Ubuntu the Linux kernel?\
    **Answer:** No. Ubuntu is a Linux distribution that includes the
    Linux kernel and many other components.

2.  **Question:** Which freedom lets you modify a program?\
    **Answer:** Freedom 1, which requires access to source code.

3.  **Question:** Where would you normally look for system-wide
    configuration?\
    **Answer:** `/etc`.

4.  **Question:** Is `/root` the same as `/`?\
    **Answer:** No. `/` is the root of the filesystem tree; `/root` is
    normally the root user's home directory.

5.  **Question:** Why is a system call needed?\
    **Answer:** It provides a controlled way for a user-space program to
    request a kernel service.

6.  **Question:** Does Linux guarantee immunity from malware?\
    **Answer:** No. Permissions and security controls help, but
    vulnerabilities, unsafe software, and misconfiguration can still
    lead to compromise.

7.  **Question:** What is the purpose of `/proc`?\
    **Answer:** It exposes process and kernel runtime information
    through a virtual filesystem.

**Study advice:** First memorize the four freedoms and the purpose of
the major directories. Then practise drawing the boot sequence and
kernel architecture from memory. Finally, run the safe inspection
commands on a Linux system or virtual machine and explain what each
output tells you.
